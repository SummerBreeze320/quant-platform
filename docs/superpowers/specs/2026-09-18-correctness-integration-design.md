# 数据与交易状态一致性修复

本轮落实项目评估中用户已同意的第一阶段：历史数据保留、统一账户与风控、行情指标语义修正。保留现有 REST 路径和请求格式，沿用当前工作区中未提交的行情接口。

## 方案

采用应用级服务上下文，通过 FastAPI Depends 从 app.state 获取。相较于模块全局单例，它允许不同应用和测试隔离；相较于数据库状态重构，本轮可在现有内存模拟系统内完成。每个应用共享一个 PaperBroker、CircuitBreakerManager、PreTradeRiskChecker、告警管理器、执行协调器、PMS 及行情服务。状态修改使用同一个进程内锁串行化。此方案不提供跨 worker 或重启持久化。

行情默认策略 hft_stream_01 通过 PMS 注册，从母账户预备金划拨现有 500 万模拟资金，避免两边独立造账。执行和信号都使用相同检查器；成交后更新共享熔断器。独立构造 ExecutionCoordinator 时也统一检查器与熔断器，拒绝显式冲突的配置。

统一柜台后，PMS 注册不得覆盖已经存在的交易账户。每笔成功的资金划转须同步调整共享熔断器：水位按划转后权益/划转前权益缩放，保留真实回撤比例、最高回撤、熔断等级与触发记录。零余额重新注资时重建资金基线，但不清除已有熔断与最高回撤。调整在每笔划转完成时发生，批量计划后续失败不撤销已完成划转对应的风险调整。

Qlib 特征采用按日历索引合并更新：保留未涉及日期，重复日期最后一条覆盖，缺口填 NaN，重复写入幂等，未涉及字段保持原样。采用同目录临时文件和 os.replace 做单文件原子替换，写入失败保留旧文件。已有特征时只允许日历尾部追加，不允许插入或删除历史日期以免索引错位；历史缺口补数须使用已存在的日历日期。禁止写入不在日历中的行情。该方案保证单文件完整性，不声称多文件事务或多进程并发写安全。

SignalEngine 保存每个标的最近一次 IndicatorValue 输出，查询只读快照，不重新计算或推进指标。布林带均值、%b、OFI 均返回真实结果；未知标的保留原有零值/中性值返回格式。回放使用 TickReplayEngine 并落实 speed（每笔间隔秒数）的语义。WebSocket 连接归属应用，跨线程推送调度回连接所在事件循环。

## 验收

- 两次每日写入仍能读出历史；重复、纠正、稀疏补数结果正确。
- 单文件替换失败不破坏历史；日历重排和非法日期明确失败。
- PMS 配资账户在执行接口可见，成交在 PMS 穿透持仓中可见。
- 风控 API 添加黑名单/触发熔断后，执行与行情信号都会拒单；复位/移除后恢复。
- 不同 create_app() 的黑名单、账户和行情互不污染。
- 用手算行情校验 VWAP、布林带和 OFI；重复查询不改变值。
- 原有测试回归，明确区分基础设施故障与断言失败。

## 不在本轮范围

真实训练预测回测链路、QMT、分布式消费恢复、母账户熔断向子账户的策略继承、持仓实时重估、持久化和认证，继续作为后续阶段。本轮只保证同一账户在各接口共享状态。
